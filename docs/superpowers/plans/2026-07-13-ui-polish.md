# UI Polish Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Clear the deferred Questline polish backlog and fix app-wide swallowed error messages: an opt-out autofocus + neutral delete toast on the detail page, a `questlineLabel` helper + color-swatch a11y, and routing 7 files' error toasts through the existing `apiErrorMessage` helper.

**Architecture:** Pure frontend, no new files. Reuse the existing `apiErrorMessage` (`@/lib/api-error`) for error text; add one back-compatible prop to `QuickAddBar`; small local helper + ARIA attributes elsewhere.

**Tech Stack:** TypeScript, React 19 + wouter, Tailwind/shadcn.

## Global Constraints

- **No backend, schema, contract, codegen, or `drizzle push`.** Frontend only.
- Preserve every existing fallback string and every toast option (`variant`/`className`/`description`) EXCEPT the two deliberate changes: (a) the delete-**success** toast drops `variant: "destructive"`; (b) error-message text is resolved via `apiErrorMessage(err, fallback)` instead of `err?.response?.data?.error`.
- `QuickAddBar`'s new `autoFocus` prop defaults to `true` — the existing Quest Log usage (`<QuickAddBar selectedDate={date} />`) must be unchanged in behavior.
- `apiErrorMessage(err, fallback)` (already in `artifacts/focusquest/src/lib/api-error.ts`) resolves `err.data.error` → `Error.message` → `fallback`, so it is a correct drop-in for both `err?.response?.data?.error ?? "x"` and `err?.response?.data?.error ?? err?.message ?? "x"`.
- Verification: `pnpm typecheck` (root) per task. The visible behavior (a11y, focus, toast text) is confirmed in the user-run browser walkthrough.
- Branch: `chore/ui-polish` (already created). Verify the branch before each commit (`git rev-parse --abbrev-ref HEAD`).

### Task 2: `questlineLabel` helper + color-swatch radiogroup a11y

**Files:**
- Modify: `artifacts/focusquest/src/pages/tasks.tsx`
- Modify: `artifacts/focusquest/src/components/questline-edit-dialog.tsx`

**Interfaces:**
- Produces: a module-scope `questlineLabel(ql)` in tasks.tsx; ARIA radiogroup semantics on the swatch row.

- [ ] **Step 1: Add the `questlineLabel` helper**

In `artifacts/focusquest/src/pages/tasks.tsx`, add a module-scope helper (near the top, beside other small helpers like `formatMinutes`):

```ts
function questlineLabel(ql: { title: string; status: string }): string {
  return ql.status === "completed" ? `${ql.title} · done` : ql.title;
}
```

- [ ] **Step 2: Use it in both selectors**

In `artifacts/focusquest/src/pages/tasks.tsx`, both the filter `<Select>` and the edit `<Select>` currently render the label as:

```tsx
                {ql.title}{ql.status === "completed" ? " · done" : ""}
```

Replace **both** occurrences with:

```tsx
                {questlineLabel(ql)}
```

(There are two — one in the filter selector's `SelectItem` map, one in the edit selector's `SelectItem` map. The create selector uses `activeQuestlines` and renders `{ql.title}` plainly — leave that one as-is.)

- [ ] **Step 3: Add radiogroup semantics to the swatches**

In `artifacts/focusquest/src/components/questline-edit-dialog.tsx`, the swatch container is:

```tsx
            <div className="flex flex-wrap items-center gap-2 mt-1.5">
```

Change it to a radiogroup:

```tsx
            <div className="flex flex-wrap items-center gap-2 mt-1.5" role="radiogroup" aria-label="Accent color">
```

On each color swatch `<button>` (the one inside `QUESTLINE_COLORS.map`), add `role="radio"` and `aria-checked`:

```tsx
                <button
                  key={c}
                  type="button"
                  role="radio"
                  aria-checked={color === c}
                  aria-label={`Color ${c}`}
                  onClick={() => setColor(c)}
                  className={`w-7 h-7 rounded-full border-2 transition-transform ${color === c ? "ring-2 ring-offset-2 ring-offset-background ring-foreground scale-110" : "border-transparent"}`}
                  style={{ backgroundColor: c }}
                />
```

On the "None" `<button>`, add `role="radio"` and `aria-checked`:

```tsx
              <button
                type="button"
                role="radio"
                aria-checked={color == null}
                aria-label="No color"
                onClick={() => setColor(null)}
                className={`px-3 h-7 rounded-full border text-xs ${color == null ? "border-foreground text-foreground" : "border-border text-muted-foreground"}`}
              >
                None
              </button>
```
